Ye Project Kya Hai?

Vendor Passport — Enterprise Audit, Compliance & Certification Platform

Ek Line Mein:

"Ye system companiyon ko apne audits, compliance, risks, certifications, aur vendors ko ek jagah manage karne mein help karta hai."

Simple Explanation

Sochiye ek badi company hai — GlobalTech Solutions. Usko apne data security ke liye ISO 27001 certificate chahiye. Usko apne vendors ka pata lagana hai ki kaun safe hai aur kaun nahi. Usko apne andar ki problems (findings) track karni hain. Ye sab kaam Vendor Passport karta hai — ek single dashboard se.

Tech Stack

BackendNode.js + Express 4
DatabaseMongoDB (Mongoose 8 ODM)
CacheRedis (token blacklisting, caching)
AIAnthropic Claude (Ask Passport assistant)

SecurityHelmet, CORS, Rate Limiting, Zod validation
TestingVitest (unit) + Playwright (E2E, 3 browsers)
DeploymentDocker + docker-compose (app + mongo + redis)

Code: canGrantRole()

// backend/shared/roles.js
function canGrantRole(actorRole, targetRole) {
  // Super Admin hi Super Admin create kar sakta hai
  if (PRIVILEGED_ROLES.includes(targetRole))
    return actorRole === 'Super Admin';
  // Organization Admin bhi baaki roles create kar sakta hai
  return actorRole === 'Super Admin' || actorRole === 'Organization Admin';
}

Permission System — Deep Dive

Ye System Kaise Kaam Karta Hai?

Role-Based Access Control (RBAC)

Is project mein Role-Based Access Control hai. Har user ka ek role hota hai, aur us role ke basis par decide hota hai ki wo kya kar sakta hai aur kya nahi.

3 Layers of Security

Layer 1: Authentication

"Tu kaun hai?" — JWT token se check hota hai ki logged-in user kaun hai.

File: backend/middleware/auth.js

Layer 2: Authorization (RBAC)

"Tujhe ye karne ki permission hai?" — Role check hota hai.

File: backend/middleware/rbac.js

Layer 3: Tenant Isolation

"Tu sirf apna data dekh sakta hai" — Super Admin ke alawa koi bhi doosri company ka data nahi dekh sakta.

File: backend/middleware/tenant.js

Authentication Flow

Browser — Login form bhara
↓
POST /api/auth/login — Email + Password bheja
↓
Login Limiter — 5 attempts per 15 min check
↓
Database — Email se user dhundha
↓
bcrypt — Password compare kiya
↓
JWT Token bana — userId, role, orgId, name
↓
Response — Token + User data wapas

Route-Level Protection Examples

// User management — Sirf Admin access
router.get('/', authenticate, requireAdmin, ctrl.list);

// Audits — Audit-related roles access
router.get('/', authenticate, requireAuditor, ctrl.list);

// Risks — Specific roles
router.get('/', authenticate, restrictTo(
  'Super Admin', 'Organization Admin',
  'Compliance Manager', 'Risk Manager', 'CA / Consultant'
), ctrl.list);

Frontend vs Backend Security

Important Security Note

Frontend mein button hide hona aur backend permission hona same cheez nahi hai!

Is project mein dono hota hai:

  • Frontend: Sidebar mein sirf wohi links dikhte hain jo role ke liye hain
  • Backend: Har route par authenticate + requireRole middleware hai

Agar koi manually URL open kare to kya hoga? Backend 403 (Forbidden) dega — permission nahi hai to access nahi milega.

Code evidence: tests/unit/auth-hardening.test.js — ye test verify karta hai ki har mounted router ko authentication chahiye.

Login Kaise Kaam Karta Hai?

Bilkul basic level par samjho.

Simple Explanation

"Jab tum login karte ho, tum email aur password daalte ho. Ab system ko check karna hota hai ki tum sach mein wahi user ho ya nahi."

"Phir system check karta hai ki tumhe kya permission hai."

"Phir tumhe ek special ticket (token) milta hai jo tum har baar saath le jaate ho."

Technical Flow

1. Browser — Login form mein email aur password type karo
↓
2. POST /api/auth/login — Email aur password server ko bhejo
↓
3. Rate Limiter — "Kitni baar try kiya?" (5 baar per 15 min)
↓
4. Validation — Email sahi format ka hai? Password hai?
↓
5. Database — Email se user dhundho (MongoDB)
↓
6. Password Check — bcrypt se compare karo
↓
7. Status Check — User "Active" hai ya "Inactive"?
↓
8. JWT Token Banao — userId, name, role, orgId daalo
↓
9. Response — Token + user data browser ko wapas bhejo

JWT Token Kya Hai?

Simple Explanation

JWT token ek "special ID card" hai. Jab tum login karte ho, system tumhe ye ID card deta hai. Ab jab bhi tum kuch maangte ho system se, ye ID card saath mein hota hai.

Logout click karo

Troubleshooting

Login Nahi Ho Raha

Check karo:

  1. Galat email ya password
  2. Account "Inactive" ya "Suspended"
  3. Rate limit hit (5 galat attempts = 15 min block)
  4. Token expire
  5. Server down — GET /api/health check karo
User Create Nahi Ho Raha

Check karo:

  • Permission — sirf Admin
  • Duplicate email in same org
  • Form validation fail
  • canGrantRole check fail
Data Dikh Nahi Raha

Check karo:

  • Sahi org mein ho? Tenant isolation
  • Role sahi hai? RBAC check
  • Database connected hai? /api/health
  • Seed data load hua hai? (Demo mode)
File Upload Nahi Ho Raha

Check karo:

  • File size 25MB se zyada hai?
  • Allowed extension hai? (PDF, images, Office, CSV, TXT)
  • Permission hai? (Employee ke paas limited access)
