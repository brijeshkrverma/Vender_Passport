### Prompt 1: Secure Database-Level Pagination (Fixing I-16)
```text
In the Vendor Passport backend, list controllers currently fetch all documents from MongoDB and then perform memory-level slicing using `.slice(skip, skip + limit)`. This is inefficient and can crash under heavy load.

Please update the pagination parsing in the following controllers to use database-level pagination:
1. `backend/modules/audits/audit.controller.js`
2. `backend/modules/findings/finding.controller.js`
3. `backend/modules/risks/risk.controller.js`
4. `backend/modules/controls/control.controller.js`
5. `backend/modules/documents/document.controller.js`
6. `backend/modules/vendors/vendor.controller.js`
7. `backend/modules/organizations/organization.controller.js`
8. `backend/modules/users/user.controller.js`

Modify their database queries to use `.skip(skip).limit(limit)` directly on the Mongoose queries. Ensure that total count is fetched via `Model.countDocuments(filter)` in parallel using `Promise.all` to maintain fast response times.
```

### Prompt 2: Safe Search / Regex Escaping to Prevent ReDoS (Fixing I-17)
```text
The backend search queries across multiple modules use unescaped user inputs directly in MongoDB `$regex` searches (e.g., `filter.title = { $regex: query.search }`). This exposes the application to Regular Expression Denial of Service (ReDoS) attacks.

Please create a helper utility to escape regular expression characters (e.g., in `backend/shared/utils.js` or `backend/shared/scope.js`):
```javascript
function escapeRegex(string) {
  return string.replace(/[-\/\\^$*+?.()|[\]{}]/g, '\\$&');
}
```
Apply this utility to all search filters where a `$regex` query is constructed in backend services (such as audits, findings, risks, certificates, documents, vendors, etc.) to ensure that special regex characters in the search term are treated as literal characters.
```

### Prompt 3: Fix `useApi` Hook Stale Closures & Header Overwrites (Fixing I-18)
```text
In the React frontend (`frontend-react/src/hooks/useApi.js`), the `useApi` hook has a dependency array that only tracks `[url]`. This causes stale closure issues if the `authHeaders` (stored in sessionStorage / context) change after login. Furthermore, when `options` containing headers is passed, it overwrites the auth header.

Please update `frontend-react/src/hooks/useApi.js` to:
1. Add necessary dependencies (like headers/token state) to the dependency array.
2. Deep merge the authorization headers with any user-provided options headers so they do not overwrite each other.
3. Test that API calls reflect the new token immediately after a user log-in or token refresh.
```

### Prompt 4: Keyboard Shortcut Overrides (Fixing I-19)
```text
The keyboard shortcut hook (`frontend-react/src/hooks/useKeyboard.js`) currently intercepts keyboard events and calls `e.preventDefault()`, which hijacks standard browser behavior such as Ctrl+A (Select All), Ctrl+F (Find), Ctrl+C (Copy), etc.

Please modify `frontend-react/src/hooks/useKeyboard.js` to:
1. Only intercept specific custom shortcuts (like `/` for focus search) if they don't conflict with system/browser shortcuts.
2. Remove any blanket `e.preventDefault()` calls on general key combinations so that standard accessibility muscle-memory shortcuts work correctly.
```

### Prompt 5: Complete Tenant Isolation (Fixing I-20 & R32)
```text
Several backend modules—specifically notifications, ccm, reports, and assessments-root—are missing proper tenant isolation checks. While service-level scoping handles basic calls, we need defense-in-depth at the route/middleware level.

Please:
1. Register the `tenantIsolation` middleware in the route files for notifications, ccm, reports, and assessments.
2. In the controllers for these modules, ensure all query filters include `orgId` scoped to the current user's org (using `req.user.scopeOrgId` or `req.user.orgId`).
3. Add tests or assertions to ensure that requesting stats or lists from these routes with cross-org IDs returns only the user's scoped organization data.
```
