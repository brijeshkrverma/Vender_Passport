Sabse pehle kaun sa role? — school wali misaal se samjho

Is app ko ek school maan lo. Har role school ke ek insaan jaisa hai. Agar tum ulta-pulta order me test karoge to har jagah "khaali page" milega — isliye order maayne rakhta hai.

Ye "relay race" hai: har row me kaun kaam karta hai → kya button dabata hai → database me kya banta hai → usse kis role ko naya kaam/access milta hai. Upar se neeche padho; upar wali row skip karoge to neeche wali row fail hogi (laal 🔒 arrow yahi dikhata hai).

STEP 8 · Compliance Manager (ya Admin / Reviewer)
CAPA banata hai — 🔒 STEP 7 ke bina possible nahi POST /api/capa — body me findingId zaroori.
rootCause · actionPlan · verificationCriteria · owner · due CAPA API sirf 4 roles ko: SA, OA, Compliance Manager, Reviewer. Auditor & Audit Manager ko 403.
capa Open → In Progress → Pending Verification → Verified → Closed
Reviewer ko: Kanban card verify/close karne ka kaam ⚠ CA / Consultant ke sidebar me CAPA dikhta hai par API 403 deta hai — ye asli mismatch bug hai.
STEP 9 · Reviewer Head Examiner — recheck
Verify + close karta hai Evidence: PATCH /api/evidence/:id/verify → Verified / Rejected
CAPA: Kanban card par ek click → POST /api/capa/:id/advance Reject kiya to Finding Reopened ho jaata hai — flow wapas Step 6/7 par.
verificationStatus · capa.status Verified / Closed
Audit Manager / Compliance Mgr ko: audit band karne ka rasta Jab tak CAPA Closed nahi, audit ko Closed dikhana galat hoga — yahi business rule test karo.
STEP 10 · Audit Mgr / Compliance Mgr Result declare
Audit close + report + certificate POST /api/audits/:id/advance (Report → Closed) · GET /api/reports/summary · /api/reports/export/:type · /certificates Reports API: SA, OA, Compliance Mgr, Audit Mgr, Risk Mgr, CA — Auditor & Reviewer ko 403.
audits.completedAt · certificates status Closed + cert record
Vendor Manager · External User · Employee ko: final output Certificate, scorecard aur expiry alerts — yahi in roles ka poora matlab hai.

Testing ke waqt in cheezon par dhyan do

Ye section update ho chuka hai. Pehle yahan 8 bugs listed the. Un sab par fix apply ho chuka hai — neeche ab kya expected behaviour hai wo likha hai. Agar aapko purana behaviour dikhe to wo genuine regression hai, bug report karo.
1 · Bina token ke API 401 deta hai. server.js me ek demo-user fallback likha hai, par har module route uske baad authenticate chalata hai jo Bearer header na hone par 401 "No token provided" throw karta hai. Ye sahi behaviour hai — fallback effectively dead code hai.
2 · Register ab naya organization banata hai — existing me join nahi karta. Ye sabse bada security fix hai. Pehle koi bhi role: "Super Admin" aur orgId: "ORG-101" bhejkar poore platform ka admin ban sakta tha. Ab:
  • orgId request se liya hi nahi jaata — server khud generate karta hai
  • role ek fixed allow-list se hi aa sakta hai; Super Admin kabhi nahi
  • Agar us naam ka org pehle se hai to 409 milega — "apne admin se invite maango"
Test karo: "GlobalTech Solutions" naam se register karo → 409 aana chahiye. Koi naya naam do → naya ORG-xxx banega aur usme aap akele honge.
3 · Register ki error ab asli wajah dikhati hai. Duplicate email, existing org name, ya rejected role — teeno ka apna message screen par aayega. Pehle har failure par "Cannot reach the server…" dikhta tha.
4 · Audits list se detail page ab khulta hai. Row par click (ya Enter) karne se /audits/<id> khul jaata hai. Pehle sirf console.log hota tha.
5 · CAPA card ab confirmation maangta hai. Card click karne par dialog aayega jisme target status likha hoga. Cancel karoge to kuch nahi hoga. Har change audit trail me record hota hai.
6 · "Advance Stage →" aur "← Back" ab kaam karte hain. Auth header ab bheja jaata hai, page reload ke bajaye data refetch hota hai, aur fail hone par error banner dikhta hai. Saath me lifecycle ka bug bhi fix ho gaya — pehle stage 5 (Execution) ke aage jaana impossible tha kyunki service ek aisi status value bhejti thi jo model ke enum me hai hi nahi. Ab poore 12 stages chalte hain.
7 · Create Audit ab failure chhupata nahi. 400/403 aane par modal khula rehta hai aur field-level error dikhata hai. Aur Compliance Manager ab audit bana sakta hai — wo requireAuditor list me add kar diya gaya hai.
8 · Stub pages ab sidebar me "SOON" badge ke saath dikhte hain. 23 nav items par ye badge hai — click karne se pehle hi pata chal jaayega ki wo page abhi bana nahi hai. Audit Trail ab stub nahi hai — wo asli page ban gaya hai (/audit-trail).
9 · Mock data ab kahin fallback nahi hota. API fail hone par "Could not load…" error state dikhta hai, fake rows nahi. Jo 4 pages sirf sample content dikhate hain (Client Portfolio, Regulatory Changes, Working Papers, AI Drafts) unke upar saaf-saaf "Sample data" banner hai.
10 · Naye rules jo ab test karne chahiye:
  • Evidence self-verification block: jo user evidence upload kare wahi use verify nahi kar sakta → 403
  • Verify sirf reviewer-class roles: Auditor, Employee, External User ab verify nahi kar sakte → 403
  • Auditor assignment: koi bhi naam type nahi chalega — active user hona chahiye; khud ko assign nahi kar sakte; audited org ka member auditor nahi ban sakta
  • Delete ab soft delete hai: record list se hat jaata hai par DB me deletedAt ke saath rehta hai
  • Audit trail: har create/update/delete /audit-trail page par dikhna chahiye, actor ke naam ke saath
  • Audit log immutable hai: uski entry ko update ya delete karne ki koshish error deni chahiye
  • Login page par role chips nahi hain — role account se aata hai
11 · Ab create/edit UI se hota hai, Postman se nahi. Pehle sirf Documents aur Evidence me create flow tha; baaki 9 entity pages read-only the. Ab in sab par create button hai:
  • Users — + Add User, Edit, Remove. Ye sabse zaroori hai: ab sign-up hamesha naya org banata hai, isliye kisi ko apne org me laane ka ekmatra tareeka yahi page hai.
  • Findings — + New Finding (audit chunna zaroori), Edit, Remove
  • CAPA — + New CAPA (finding chunna zaroori)
  • Risks · Controls · Certificates · Vendors — apne-apne create buttons
Topbar ka + Create menu ab seedha wo dialog kholta hai (?new=1 se), sirf list page par chhod nahi deta.
12 · In create flows ko test karo:
  • Required field khaali chhodo → dialog band nahi hona chahiye, upar "Required: …" dikhna chahiye
  • Organization Admin se user banate waqt role Super Admin chuno → 403 (list me option tabhi dikhega jab aap Super Admin ho)
  • Finding banate waqt audit na chuno → form hi rok dega; API par bhejo to 400
  • Naya user banao → uske email/password se login karo → uska role sidebar me reflect hona chahiye
  • User ko Remove karo → wo login nahi kar paayega (401) par /audit-trail me uske purane actions rahenge
  • Har create/edit/remove ke baad /audit-trail kholo → entry actor ke naam ke saath dikhni chahiye
