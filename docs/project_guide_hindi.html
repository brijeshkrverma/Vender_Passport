🏢 1. व्यवसायिक अवलोकन (Business Overview)

Vendor Passport एक एंटरप्राइज़ गवर्नेंस, रिस्क और कंप्लायंस (GRC) प्लेटफॉर्म है जो बड़ी कंपनियों और उनके सप्लायर्स/वेंडर्स के बीच सुरक्षा ऑडिट, सर्टिफिकेशन ट्रैकिंग और रिस्क असेसमेंट को डिजिटल बनाता है।

🚨 क्या प्रॉब्लम है?
  • वेंडर्स के ISO 27001, SOC 2, PCI DSS, GDPR सर्टिफिकेट्स स्प्रेडशीट्स में मैनेज होते हैं।
  • ऑडिट फाइंडिंग्स, CAPA और एविडेंस अलग-अलग टूल्स में रहते हैं।
  • किसी वेंडर के सर्टिफिकेट एक्सपायर होने पर पता नहीं चलता।
  • टीमें मैनुअल रिपोर्ट्स बनाती हैं जो समय लेती हैं और गलतियाँ हो सकती हैं।
  • एक्सटर्नल ऑडिटर्स और कंसल्टेंट्स को केवल उनका क्लाइंट डेटा दिखाना मुश्किल होता है।
✅ Vendor Passport कैसे मदद करता है?
  • Single Source of Truth: सभी ऑडिट, फाइंडिंग्स, सर्टिफिकेट्स, एविडेंस एक ही डैशबोर्ड पर।
  • Automated Compliance Tracking: 90-दिन एक्सपायरी अलर्ट्स, CCM और रिस्क रजिस्टर।
  • Role-Based Access: हर रोल को सिर्फ़ वही डेटा और पेज मिलते हैं जो उसके काम के हैं।
  • AI Assistant: "Show overdue findings" जैसे सवालों के जवाब तुरंत मिलते हैं।
  • Vendor Self-Service: वेंडर अपने सर्टिफिकेट और एविडेंस खुद अपलोड कर सकते हैं।

🧱 4. तकनीकी वास्तुकला (Architecture)

निम्नलिखित आर्किटेक्चर Business Analysts को यह समझने में मदद करता है कि डेटा कहाँ से आता है, कहाँ सेव होता है और कौन-सी टीम किस हिस्से की ज़िम्मेदार है।

🖥️ Frontend — React SPA
  • Framework: React 18 + React Router DOM v6
  • Styling: Tailwind CSS + Custom CSS Variables
  • Build: Vite (dev server 5173, production dist served by Express)
  • State: AuthContext (user, token, role) और ToastProvider
  • Key Components: Sidebar, Topbar, Drawer, AssistantPanel, Modal, Charts
  • Guard: ProtectedRoute — अगर रोल के पास पेज एक्सेस नहीं तो /dashboard पर रिडायरेक्ट
🛠️ Backend — Express REST API
  • Runtime: Node.js + Express 4
  • Database: MongoDB + Mongoose 8
  • Cache: Redis (Docker Compose में)
  • Security: Helmet, CORS, express-rate-limit, JWT
  • Modules: 18 modular routes under backend/modules/
  • Fallback: MongoDB न होने पर demo mode में in-memory mock data
🗄️ Mongoose Collections / Data Entities

📊 6. डैशबोर्ड डीप-डाइव

डैशबोर्ड हर रोल के लिए एक "command center" है। Business Analysts के लिए यहां KPI cards और charts का मतलब:

📈 4 मुख्य KPI Cards
  • Active Audits: वर्तमान में चल रहे ऑडिट। ज़ीरो होने का मतलब — कोई ऑडिट प्रोग्राम नहीं चल रहा।
  • Open Findings: अनसॉल्व्ड कमियाँ। यह compliance health का मुख्य संकेतक है।
  • Expiring Certs: अगले 90 दिन में एक्सपायर होने वाले सर्टिफिकेट।
  • High Risks: रिस्क स्कोर ≥ 15 — तुरंत ध्यान देने की आवश्यकता।
📊 Analytics Widgets
  • Audit Status Breakdown: Planning, Execution, Closed में कितने ऑडिट हैं।
  • Findings by Severity: Critical (लाल), High (नारंगी), Medium (नीला), Low (हरा)।
  • Expiring Certificates List: रिन्यूअल countdown और status tag।
🧩 7. 18 मॉड्यूल्स का विस्तृत विश्लेषण

प्रत्येक मॉड्यूल को एक business capability के रूप में समझें — यह क्या problem solve करता है, कौन input देता है और कौन output देखता है।

📋 1. Audits & Universe

Problem: ऑडिट्स अलग-अलग जगह tracked।

Solution: 12-stage lifecycle, scope, lead auditor, due date।

Owner: Compliance Manager, Audit Manager, Auditor

⚠️ 2. Findings Tracker

Problem: कमियाँ खो जाती हैं या ओवरड्यू हो जाती हैं।

Solution: Severity, due date, owner, re-open workflow।

Owner: Auditor, Compliance Manager, Reviewer

🔄 3. CAPA Board

Problem: Corrective action की progress पता नहीं।

Solution: Kanban board: Open → In Progress → Verified → Closed।

Owner: Compliance Manager, Reviewer

⚡ 4. Risk Register

Problem: जोखिम स्कोर नहीं मापे जाते।

Solution: Inherent/Residual risk, heatmap, mitigation controls।

Owner: Risk Manager

🛡️ 5. Controls Testing

Problem: कंट्रोल्स की परीक्षण स्थिति अज्ञात।

Solution: Design/Operating effectiveness, coverage, test results।

Owner: Auditor, Compliance Manager

📜 6. Framework Taxonomy

Problem: कई frameworks (ISO, SOC, GDPR) अलग-अलग manage।

Solution: एक taxonomy से सभी controls map।

Owner: Compliance Manager

🔑 7. Certificates Engine

Problem: वेंडर सर्टिफिकेट्स एक्सपायर हो जाते हैं।

Solution: Repository + 90-day expiry alerts + renewal workflow।

❓ 14. अक्सर पूछे जाने वाले प्रश्न

Q1. क्या यह सिस्टम MongoDB के बिना चल सकता है?

हाँ, demo mode में। यदि MongoDB connect नहीं होता, तो Express mock user और in-memory data से चलता है। लेकिन production deployment में MongoDB + Redis required हैं।

Q2. क्या AI Assistant के बिना app काम करेगी?

हाँ, AI Assistant optional है। यदि ANTHROPIC_API_KEY missing है, तो AI endpoints 500 error दे सकते हैं, बाकी सभी modules ठीक चलेंगे।

Q3. External Company User क्या क्या कर सकता है?

सिर्फ़ अपनी org (ORG-103 SecureCore) का डेटा देख/अपलोड कर सकता है। Audits, Findings, Risks, Controls, CAPA, Users, Settings आदि block हैं।

Q4. RBAC frontend और backend दोनों पर है?

हाँ, frontend में ProtectedRoute redirect करता है; backend में requireRole middleware 403 Forbidden देता है।

Q5. नया module add करने का process क्या है?

1) backend/modules/<module> में routes, controller, service, model बनाएं। 2) server.js में route register करें। 3) frontend-react/src/pages में page बनाएं। 4) App.jsx में route add करें। 5) AuthContext.jsx में RBAC navigation update करें।
